# packages/link-preview – `@squorli/link-preview`

Part of the project description. The entry point is the root [AGENTS.md](../../AGENTS.md) (commands, definition of done, cross-cutting conventions, the map of all documentation in its section 0). What the feature is, the user's wishes and what was checked: `docs/features/link-previews.md`.

**This whole package is the source of a byte-identical copy in `../squorli-directory/packages/link-preview/`** (the directory looks links up for senders of direct messages who use a browser). Sync in the same work step and check with `diff -r`, root `AGENTS.md` section 2a.

## Structure

```
packages/link-preview/   @squorli/link-preview: node only, no dependencies, consumed as TypeScript source (no build step); exports "." and "./worker"
  src/addresses.ts       `isInternalAddress` (BlockList of private, loopback, link-local, CGNAT, multicast, benchmark, documentation and IETF protocol ranges and, for IPv6, `::/96` (loopback and the IPv4-compatible spelling), 6to4, Teredo, both NAT64 prefixes and site-local; IPv4-mapped spelling included; `addresses.test.ts`, 4 tests), `checkHost` (every address of a name must be public), `publicLookup` (DNS hook for http(s).request: the address actually connected to must be public)
  src/fetch.ts           `safeGet`: one guarded GET: http(s) only, no credentials in the address, `checkHost` + `publicLookup` at every hop, at most 5 redirects followed by hand, one deadline (6 s), byte caps per content type counted after decompression (gzip, deflate, brotli), `cut` (a page is cut at its cap, a picture over its cap is none), `enough` (asked with each piece that arrives plus the ENOUGH_OVERLAP = 16 bytes before it, never with everything so far: `lookup.ts` stops at `</head>`); `testOrigin` exempts one origin, for tests only; `fetch.test.ts` (2, against a local server: the marker split across two pieces)
  src/parse.ts           pure, tested: `parsePageMeta` (Open Graph, Twitter card, description, title; head only, no scripts or comments) as ONE LINEAR PASS (security audit of 5 October 2026, H-1: index based, `scanHead` + a hand-written attribute scanner, no backtracking expression; a comment, script or tag without its end ends the head, a title without its end has no title; TAG_MAX = 16 KB per tag, META_MAX = 256 meta tags), `decodeEntities`, `cleanText` (one line, no control or bidi characters, cut), `decodeHtml` (charset from the header, then a `<meta>` in the first 2 KB, then utf-8), `sniffImage` (PNG, JPEG, WebP, GIF by their bytes; no SVG); `parse.test.ts` (12: the four of before, the five hostile 512 KB inputs with a time bound, the limits, 300 seeded well-formed heads compared with the earlier parser kept in the test as the oracle, 100 pages of random tag soup)
  src/headParser.ts      `createHeadParser({ workerFile, budgetMs = 1000, idleMs = 60 s, execArgv, warn })` -> `HeadParser` (`parse(body, contentType, baseUrl)` -> PageMeta | null, `close()`, `mode`): reads a page's head in ONE worker thread with a wall-clock budget; a page not read in time is terminated with its worker and counts as unreadable (null = no preview), the next page gets a fresh worker; started lazily, stopped after idle time, never keeps the process alive (`unref` between pages); heap of the worker 128 MB; the bytes are copied once and transferred. Without `workerFile`, or when the worker never says `ready` (file missing, no loader), every page is read on the calling thread with one warning (`inline`): a preview is never worth a feature that stops working. `parseHead` = decode + parse on the calling thread. `headParser.test.ts` (6, against a stand-in worker written as plain JavaScript: queue, budget + fresh worker, crash and exit, missing file -> inline, idle stop, close)
  src/worker.ts          `runHeadParserWorker()` = the worker's side (`ready`, then one answer per job); exported as `@squorli/link-preview/worker` and called by each consumer's own entry file, which the consumer bundles next to its main bundle and names as `workerFile`: chat server `apps/server/src/preview-worker.ts` -> `dist/preview-worker.js` (under tsx: the .ts file itself, the worker inherits tsx through `process.execArgv`), directory `apps/directory/src/preview-worker.ts` -> `dist/preview-worker.js`, desktop app `apps/desktop/src/main/previewWorker.ts` -> `out/preview-worker.cjs`
  src/youtube.ts         `lookupYoutube` / `readOembed`: a video's title and embeddability from YouTube's oEmbed address (also used by the web radio)
  src/lookup.ts          `lookUpPage(url, { testOrigin?, parser? })` and `lookUpYoutubeVideo(videoId, options)` -> `LinkLookup` (kind, site name, title, description, the picture as bytes with its type) or null = no preview; with `parser` the head is read by that `HeadParser`, without it on the calling thread. The caller recognises a YouTube link (the protocol's `youtubeVideoOf`; this package must not import the protocol package, whose chat part the directory does not have) and decides what becomes of the picture
```

## Conventions

- **Security first:** nothing here may follow a redirect by itself, skip `checkHost` for a hop, read an answer without a cap or trust a content type for what bytes are. A change to `addresses.ts` or `fetch.ts` needs a run of the chat smoke test with `LINK_PREVIEW_TEST_ORIGIN` (it checks that a redirect to another local port is never asked) and of `playlist.test.ts` in the server (it pins the address rules).
- **Linear or not at all:** everything that reads a foreign page (`parse.ts`, the `enough` check in `fetch.ts`) must do bounded work per byte; no regular expression with an unbounded quantifier that has to find a closing token in the page (`[\s\S]*?`, `[^>]*` and the like), no re-scan of what was already read. A new scan gets a hostile 512 KB input in `parse.test.ts` with a time bound, like the five there. The smoke tests of both repos post a page of 512 KB `<meta ` and check that `/api/health` keeps answering.
- No dependencies and no import of `@squorli/protocol`, so the copy in the directory repo stays self-contained.

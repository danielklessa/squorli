Security release after the audit of 5 October 2026. Works with every server version; the new protections apply in full against Squorli Server 0.10.4. (0.12.6 was tagged the same day and never published: its build did not start.)

## Security

- **A link in a direct message could stall the app.** The previews of direct messages are made by the sender's own app, which read a crafted web page for about 20 seconds without responding. The page head is now read in one pass and in a worker thread with a time budget of one second; a page that is not read in time simply gets no preview.
- **Password backups use Argon2id** instead of PBKDF2 (64 MiB of memory per guess, far harder to crack from a stolen database). An existing backup keeps working and is stored anew after your next sign-in with the password; a new or changed password is at least 12 characters now. Against a server or directory from before this version the app makes backups as before.
- **Linux updates are checked by signature.** The AppImage installs an update only after the detached GPG signature next to the release file was verified against the release key built into the app; Windows installers were already code-signed and checked.
- **Device-bound sessions sign the request body** against Squorli Server 0.10.4 and later, so a captured proof fits nothing but its own request.
- **Every control link needs the key.** The links of Einstellungen > Tastenkürzel for a Stream Deck or a macro now all carry the installation's key, also `mic-off` and `deafen-on`, which were keyless until now; a web page could have triggered those two in a loop. **Copy those two links again from the tab**; the others are unchanged.
- **The debug panel masks incoming messages** as it masked outgoing ones.

## Fixed

- A message with thousands of closing parentheses no longer costs a square-time scan when the app looks for links to preview.

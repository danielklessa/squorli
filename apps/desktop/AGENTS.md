# apps/desktop – Desktop app (`@squorli/desktop`)

Part of the project description. The entry point is the root [AGENTS.md](../../AGENTS.md) (commands, definition of done, cross-cutting conventions, the map of all documentation in its section 0). Whoever adds, removes or repurposes a file here, or changes a convention or pitfall, updates this file in the same step. Decisions, phases and what was checked: `docs/features/desktop.md`.

**The app has no renderer code.** It is an Electron shell around the web client: the window shows the build of `apps/web` (`apps/web/dist`) from `app://squorli`. Everything a user sees is changed in `apps/web`; what differs between browser and app goes through `apps/web/src/platform/` (`Platform`, the bridge contract `bridge.ts`). After a client change run `pnpm build` (root) before `pnpm --filter @squorli/desktop start`; `pnpm dev:desktop` shows the Vite server instead.

## Packaging and releases

- Local installer: `pnpm build` (root), then `pnpm --filter @squorli/desktop dist` -> `apps/desktop/release/` (`Squorli-Setup-<version>.exe`, its `.blockmap`, `latest.yml`, `win-unpacked/`). Unsigned on a developer's machine (`build/sign.cjs` logs "not signed" per file; `CSC_IDENTITY_AUTO_DISCOVERY=false` avoids a certificate search).
- **Code signing (4 October 2026, `docs/features/desktop.md` "Code signing"; security audit C3 / 3.1):** the release workflow signs the Windows executables with Certum's "Open Source Code Signing in the Cloud" certificate (subject `CN=Open Source Developer Daniel Klessa, O=Open Source Developer, S=Niedersachsen, C=DE`; the private key stays in Certum's HSM) through `ssign` (MIT, an independent SimplySign client whose source was read before it was trusted; built on the Windows runner with `cargo install ssign --version <SSIGN_VERSION> --locked` from crates.io and cached by version; a new version = read its diff first, then bump `SSIGN_VERSION` in the workflow). electron-builder brings every executable to `build/sign.cjs` itself: the two native helpers while it copies the extra resources, `Squorli.exe`, NSIS's `elevate.exe`, the uninstaller and the installer, 6 signatures per build (checked locally with a stand-in for ssign, 4 October 2026), sha256 only. The Linux files get detached GPG signatures (`*.asc`) by the key "Squorli Desktop Releases <signing@squorli.com>", fingerprint `E62D 34CB F884 0496 931F B534 580D 3789 5466 FC24`, public half on the website (`squorli-website/public/squorli-desktop.asc`), which also links the signatures on the download page. **Secrets** live only in the GitHub environment `signing` (the build job's `environment:`; Settings > Environments > signing > Required reviewers = the owner, so every build waits for a click): `CERTUM_EMAIL`, `CERTUM_OTP` (the SimplySign account's TOTP seed: whoever has it signs as the project, rotate = re-issue the QR code at Certum and replace the secret), `GPG_PRIVATE_KEY`, `GPG_PASSPHRASE` (the user keeps copies outside the repos). A tag build sets `SQUORLI_SIGN_REQUIRED=1` and fails unsigned, then checks every signature with `Get-AuthenticodeSignature`; a test build without secrets is built unsigned. **`win.signtoolOptions.publisherName`** (there since electron-builder 26, not under `win` directly) holds that subject as a list (set 4 October 2026 from the first signed test build): electron-updater checks the downloaded installer's subject against it before installing, and a wrong value makes that version refuse every later update, so a renewed certificate with another subject is *added* to the list, never swapped in. SmartScreen keeps warning until the new certificate has earned reputation; nothing in the build changes that.
- **Release:** the skill `desktop-release` (`.claude/skills/desktop-release/SKILL.md`, user's wish of 20 September 2026) prepares it: it reads what changed for the app since the last `desktop-v*` tag (`docs/MILESTONE-LOG.md` is the source, the commit subjects are too terse), proposes version numbers with reasons, sets the chosen one and writes `release-notes/<version>.md`; it never tags or pushes. By hand the same: set `version` in `apps/desktop/package.json`, write the notes file, commit, tag `desktop-v<version>` (the workflow refuses a tag that does not match). The GitLab push mirror carries the tag to GitHub, where `.github/workflows/desktop-release.yml` builds on windows-latest and ubuntu-latest and collects exe, blockmap, AppImage, deb, `latest.yml` and `latest-linux.yml` in a **draft** release. A person tests and publishes the draft; the update feed follows from squorli-website (P4). Tags `v*` are the server image's; both pipelines' image jobs ignore `desktop-v*`. GitLab builds no installers.
- The deb package names its maintainer in `electron-builder.yml` (`linux.maintainer`: Daniel Klessa, desktop@squorli.com; the user's decision of 18 September 2026, the address is public with the package). Without it the deb target fails.
- **The job `release` fails with `HTTP 502` (or another 5xx) from `api.github.com`** (seen with `desktop-v0.9.2`, 28 September 2026): GitHub's API failed while the draft was created, the installers are built and kept as artifacts. On the run's page: "Re-run jobs" > "Re-run failed jobs"; it repeats that job alone within seconds, and a draft that was created after all is found and filled. No new tag, no new version.
- **Trying the release workflow without spending a version:** Actions > "Desktop release" > Run workflow on a branch with the tag field empty = a test build (artifacts only, no tag check, no release). First run of `desktop-v0.1.0` (18 September 2026) failed at `pnpm licenses`: pnpm has a built-in command of that name that hides the script; the workflow uses `pnpm run`.
- Third-party notices: Electron ships its own `LICENSE.electron.txt` and `LICENSES.chromium.html`; the main bundle contains zod and @noble (already in the web client's list) and, since P4, electron-updater with its dependencies (MIT and similar). Since 27 September 2026 `tools/licenses.mjs` walks that graph too (`DESKTOP_ROOTS`, marked "desktop app only"; `docs/features/licenses.md`): a new import in the main process or preload means a new entry there.
- `build/installer.nsh` (27 September 2026): the uninstaller deletes every registry entry the app writes itself (AppUserModelId, `Classes\squorli`, the autostart values), not on an update (`${isUpdated}`). A new registry entry in the app needs a line there.
- The unpackaged app's AppUserModelID is `com.squorli.desktop.dev`, never the installer's: a Start menu shortcut "Electron" of the development app with the installer's id renames the installed app's notifications (27 September 2026).
- Notifications' sender and full screen (27 September 2026): `registerAppId` writes `HKCU\Software\Classes\AppUserModelId\com.squorli.desktop` (DisplayName, IconUri = a copy of `build/icon.png` in userData) at every start, else Windows names the toast "electron"; the system watch helper answers `busy<TAB><request>` (`SHQueryUserNotificationState` and the foreground window covering its monitor; `shell32.lib` in `native/build.mjs`), `systemWatch.fullscreenBusy()` asks it before a notification without `inFullscreen`.
- Notifications (27 September 2026, `docs/features/notifications.md`): the client sends `{ title, body, tag }` over `IPC.notify`, `main/index.ts` `showNotification` shows an Electron `Notification` (silent, referenced until clicked or closed, `build/icon.png` on Linux, now in `electron-builder.yml` `files`) and sends the tag back over `IPC.notificationClick` after focusing the window; `main/notifications.ts` checks what arrives.
- **Testing updates without touching an installed app:** build the new version (`dist`), build an old one with `electron-builder --dir -c.extraMetadata.version=<old> -c.directories.output=<scratch>`, write `resources/app-update.yml` there by hand (`provider: generic`, a local `url`, an own `updaterCacheDirName`), serve a manifest locally, watch the states over the DevTools protocol and **kill the test app hard**: a graceful quit runs the downloaded installer.

## Conventions

- **Security baseline, do not weaken:** `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`; every `ipcMain` handler checks `isClientFrame(event)`; nothing reaches `shell.openExternal` except through `openExternal()` (http, https, mailto); child windows get no preload; a packaged app ignores every development argument. New IPC channels are added to `IPC` in `apps/web/src/platform/bridge.ts`, to the preload bridge and to `Platform`, in that order.
- **`ipcMain.on` for `sendSync`: assign `event.returnValue` exactly once.** Electron sends it at the first assignment; a default set first (`event.returnValue = null`, then the real value) answers the default for ever, silently. Compute the answer, then assign (`secrets.ts`).
- **The page never gets a seed (4 October 2026, security audit C1):** the account keys' seeds live in the main process (`keyVaultLogic.ts`); the page names a key by its public half and gets signatures, derived keys and backups. `secrets.ts` strips a `privateKey` out of every entry it hands out or takes in. A new message format the account's key signs needs its first line in `SIGNABLE_FIRST_LINES`, or the desktop app cannot sign it (the test lists them); what the device key signs stays in the page.
- **`app://squorli` is final once a public version exists.** The client keeps the directory servers' sessions in that origin's localStorage (the keys moved to `safeStorage` on 25 September 2026, `secrets.ts`; where it is not available they stay there too); renaming scheme or host loses them for every user.
- **Pure logic goes into its own module with tests** (`appFiles.ts`, `navigation.ts`, `userAgent.ts`); the Electron-bound files stay thin. `bridge.ts` and `deepLink.ts` of the web package must stay DOM-free: the main process bundles and runs them. (The compiler does not enforce it: the protocol package they pull in needs the DOM library's `CryptoKey` type, so this package is typechecked with the default libraries like the server.)
- **Tests must not import `electron`:** the package's entry throws when its binary is missing, which is the case in CI (`ELECTRON_SKIP_BINARY_DOWNLOAD=1`). Keep what is tested in modules without that import.
- The fixed directory is `https://directory.squorli.com`; `--directory-url` exists for development only.

## Known pitfalls

- **`ELECTRON_RUN_AS_NODE=1`** (set by VS Code in its terminals, also for agents run from it): Electron starts as plain Node, `require("electron").app` is undefined and the app dies with "Cannot read properties of undefined (reading 'isPackaged')". Start through `scripts/run.mjs` (the `dev`/`start` scripts do) or remove the variable.
- **Electron's binary after `pnpm install`:** pnpm 10 only runs install scripts of packages listed in `onlyBuiltDependencies` (pnpm-workspace.yaml lists `electron`). If `node_modules/electron/dist` is missing anyway (it was, right after adding the package on 18 September 2026), run `node node_modules/electron/install.js` in `apps/desktop`. CI test jobs and the Docker build set `ELECTRON_SKIP_BINARY_DOWNLOAD=1`: they never start the app.
- **Twitch and YouTube under `app://`:** without help Twitch refuses to be framed (its `frame-ancestors` names `https://<parent>`, and the parent is the host name `squorli`) and YouTube shows "Fehler 153" (no http(s) referrer). `letPlayersEmbed()` drops `frame-ancestors` for `https://player.twitch.tv/*` and sets `Referer: https://squorli.com/` for `https://www.youtube-nocookie.com/embed/*`, for exactly these hosts. Checked with and without it on 18 September 2026 (`--no-player-fix`).
- **Driving the app from a script:** start `electron.exe <apps/desktop> --remote-debugging-port=<port> --user-data-dir=<dir>` (variable above removed) and attach over the DevTools protocol. `--use-fake-device-for-media-stream` gives a microphone; **never add `--use-fake-ui-for-media-stream`**: it answers `getDisplayMedia` itself and the picker never appears. `Runtime.evaluate` ignores the page's CSP unless `allowUnsafeEvalBlockedByCSP: false` is passed.
- **`pnpm dev:desktop` works on its own:** the app loads the web client from the Vite dev server on 5173; `scripts/run.mjs` starts that server itself when nothing answers there and stops it with the app (since 26 September 2026, after the user's report that a stopped chat server, tested on purpose, left the app with the start window's "dev server does not answer"; before that day an empty window without a title bar). A Vite already running (`pnpm dev`) is left alone. The chat server on :3000 is not needed for the app to come up: a rail server that does not answer gets the notice with the countdown (docs/features/offline.md). A hidden `BrowserWindow` never answers `Page.captureScreenshot` over the DevTools protocol: give such calls a time limit.
- **`app.getLocale()` is only reliable after `ready`** (Windows answers "" before): index.ts reads it inside `whenReady` for the shell's language. **Electron 44's `clipboard` is the promise-based one** (`writeText` returns a promise, `write([new ClipboardItem({...})])`, `read()`); the old `writeImage`/`availableFormats` are gone.
- **Electron's icon in the task bar** belongs to an unpackaged app (`electron.exe`); the window's `icon` and the AppUserModelID make Windows show Squorli's. A packaged app has the icon in its executable.
- **The window is frameless (`frame: false`) in every mode** and the client draws the title bar (`apps/web/src/TitleBar.tsx`). `transparent` cannot change on a living window: a change to or from the see-through mode needs `app.relaunch()`; never try to toggle it at run time. Overlays of the client must start below the title bar (`--titlebar-h`), or a dialog blocks moving and closing the window.
- **A registered global shortcut never reaches any window, ours included** (`globalShortcut` takes the combination from every program): whoever captures a key in the client must have the shell let the shortcuts go first (`IPC.hotkeysSuspend`), and the push-to-talk key must never be a shortcut (the helper watches it instead, docs/features/hotkeys.md). `globalShortcut` on Linux works with X11 only.
- **Without the system watch helper** the app works and the AFK detection does not see controllers (`DesktopInfo.systemWatch` false, `platform.systemActivity` null), and the push-to-talk key works in the window only (`DesktopInfo.hotkeys.globalPtt` false). Chromium's Gamepad API is no replacement: it delivers only while the window has the focus (the user's test, 21 September 2026).
- **Without the native helper** (not built, `pnpm --filter @squorli/desktop native` needs Visual Studio or the Build Tools with the C++ workload) the app works and a share offers the whole system's audio for screens only, the app's own sound included. `DesktopInfo.nativeScreenAudio` tells the client which way it is.
- **Processes named electron.exe may be the user's own running app.** Test instances carry `--remote-debugging-port` and a scratchpad `--user-data-dir` in their command line (`Get-CimInstance Win32_Process`); never kill Electron processes by name. With `closeToTray` on, a closed window leaves the app running by design.
- **Windows Firewall** asks once for "Electron" when the first voice connection opens its UDP port (unpackaged app; a packaged one asks for "Squorli").
- Cancelling the picker reaches the page as `AbortError` ("Invalid capture constraints"), which the voice client already treats as a cancel.
- **`desktopCapturer.getSources` with thumbnails is slow for windows** (measured 28 September 2026: 18 windows 3.2 s, 3 screens 0.4 s, the list alone with thumbnail size 0 and the window icons 0.4 s). Never put it in front of something the user waits for: list first, pictures afterwards (`displayMedia.ts`). Calls with different options run side by side; a call cannot be cancelled. Questions over the DevTools protocol wait while the main process lists, so measure in the page.

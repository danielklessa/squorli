Plugins: one JavaScript or TypeScript file that your server runs itself, in a sandbox, for what only some communities want. Two ship with the server: roles for a limited time, and birthday congratulations. One migration and five new variables with defaults. Desktop app 0.17.0 follows with the same client.

## Before you update

- **Nothing to do by hand.** Installations with automatic updates take this version by themselves once it is published. The update adds tables for plugins to the database (they cannot be taken back); `squorli update` backs up first, as always.
- **Plugins are available after the update, and nothing runs until an owner installs one.** By default an owner can upload plugins in Administration > Plugins. Set `PLUGINS=operator` in `.env` to leave installing to the command on the machine, or `PLUGINS=off` to have no plugins at all.
- **New variables, each with a default:** `PLUGINS` (`owner`), `PLUGIN_MAX` (20 plugins), `PLUGIN_CPU_MS` (200 ms of CPU time per event), `PLUGIN_MEMORY_MB` (32 MB per plugin), `PLUGIN_STORAGE_MB` (5 MB per plugin in the database). A plugin costs memory only while it runs: up to about 46 MB each, and an idle one is stopped after five minutes.
- **The command `squorli plugin`** comes with this update on Windows. On Linux the `squorli` command itself is renewed when you run the installer again and choose "Update"; until then use Administration > Plugins.
- **Desktop app:** 0.17.0 follows with the same client. Older apps keep working with this server: they show a plugin's message as a plain notice line and have neither the Plugins tab nor a plugin's commands and menu entries. The browser client comes with the server.
- **New, and not yet proven in the field.** Plugins were tested in automatic tests and on test installations, including the published image run read-only. They were not yet run on the package for Windows, on a server in daily use, or for days at a time.

## New

- **Plugins.** A plugin is one file that the server runs in a sandbox of its own: it gets the JavaScript language and a fixed set of functions, and no access to files, the network, the database or your configuration. It never puts code into anybody's app; what it shows is drawn by the app. An owner installs one in Administration > Plugins ("Datei hochladen …"), and switching it on first lists in whole sentences what it may do. A plugin touches only the roles and channels picked in its settings, and never a role with administrator rights. One event of a plugin gets a fixed budget of time and memory; a plugin that overruns is stopped without touching the others, and five failures within ten minutes suspend it until an owner starts it again. Each plugin has its log on its page.
- **What a plugin can add:** slash commands in the message field (type `/`), entries in a member's menu with a small dialog, messages under its own name, reactions to members joining and to role changes, tasks for later that survive a restart, and tables on its page in the administration.
- **Timed roles** ships with the server and waits under "Verfügbar". Pick the roles it may give, then right-click a member, "Rolle auf Zeit…", choose the role and for how long. When the time is up the role is taken away again; "Laufende Zuweisungen" shows who has what until when.
- **Birthdays** ships as well. Members enter their birthday with `/geburtstag` or `/birthday`, with or without the year, and take it out again in the same form. On the day the plugin congratulates them in the channel you picked, with their age if they gave the year. `/geburtstage` or `/birthdays` shows who comes next, to the person who asks only. An entry goes when its member leaves the server.
- **`squorli plugin`** on the machine: `list`, `add <file>`, `add --bundled <id>`, `enable`, `disable`, `remove`, `log`. It shows what a plugin may do and asks before it switches one on.
- **Write your own.** The guide is at https://squorli.com/en/docs/plugins/ (German: https://squorli.com/de/docs/plugins/), the interface with every event and function in `packages/plugin-api/index.d.ts` of the repository, with two examples next to it.

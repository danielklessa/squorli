Voice and video on a home connection whose public address changes, and a sign-in fix for server accounts.

## Before you update

- **Nothing to do by hand** for an installation made with the install script or the Windows package: no database migration, no deploy file to fetch again. Installations with automatic updates take this version by themselves once it is published.
- **New optional variables:** `LIVEKIT_DYNAMIC_IP`, `LIVEKIT_ROUTER_IP` and `LIVEKIT_NODE_IP_URL` (see "New"). Leave them out and nothing changes. A Portainer stack has no installer and so no job for a changing address.
- **Desktop app:** older apps keep working. A new desktop app with the same sign-in fix as the browser client of this release follows.
- No newer Squorli Directory is needed. The job for a changing address asks the public Squorli directory as a fallback when the router does not answer.

## New

- **A changing public address (home connection).** Behind a home router the public address changes at every forced reconnection, and voice and video stopped working until somebody entered the new one. The installer now asks whether the address changes and sets up `squorli nodeip`: every 5 minutes it asks the router by UPnP for the public address (else a web address that answers with it), and when it changed it writes it into the settings and restarts LiveKit (on Windows together with the app server, which depends on it). `squorli nodeip` shows the state, `squorli nodeip check` checks right now, `squorli nodeip on [minutes]` and `off` switch the job. On Windows it is a task of the task scheduler. To switch an existing installation to it, run the installer again (Linux: "Einstellungen ändern", Windows: the setup) and choose "it changes" at the question about the public IP address.

## Fixed

- **An existing server account always signs in,** also on a server that does not take new server accounts. The owner of such a server who had registered with the setup code was refused at the sign-in form after signing out; the switch now decides who may register and nothing more.
- **The connection check probes the right address** on an installation with a changing public address.

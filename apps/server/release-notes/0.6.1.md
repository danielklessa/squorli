Squorli Server can keep itself up to date now, and an update stops only what it has to.

## Before you update

- **Nothing to do by hand:** no migration, no new variable, no file to fetch. Installations with automatic updates will take versions like this one by themselves.
- **Linux, installed with the install script:** the new commands belong to the `squorli` command the script writes. `squorli update` brings the new image only; to get the commands, run the install script again and choose "Update".
- **Windows:** `squorli update` brings everything.
- **No new desktop app and no newer Squorli Directory are needed.**

## New

- **Automatic updates.** `squorli autoupdate on` sets up a job that looks for a new version and installs it. It asks how often, from every hour to once a day; with 24 hours it runs at 04:17. When nothing is new, nothing is stopped or started. Every update makes a backup first. `squorli autoupdate` shows the state and the last runs, `squorli autoupdate off` removes the job. On Linux the job follows the image tag in `APP_IMAGE`, so it needs `latest` there; a fixed version never changes by itself. Read the warning the command shows before you answer: an update restarts the app server whenever a version appears.
- **A version that needs you waits for you.** When a version asks for work by hand before the update, the job does not install it. It notes the version in its log and waits for your `squorli update`, which names the release notes and asks whether that work is done.
- **Only look.** `squorli update --check` (on Windows also `-Check`) tells whether there is something new and changes nothing that runs; its exit code is 10 when there is, 0 when not.

## Improved

- **An update on Windows stops only what changed.** When a new version brings a new Squorli but the same PostgreSQL and LiveKit, these two keep running and only the app server restarts. Until now every update stopped all services.
- **`squorli update` on Linux backs up first,** as on Windows, and says which services get a new image; the containers whose image stayed the same keep running. A backup that fails stops the update; `--no-backup` leaves it out.
- **`squorli backup` on Linux** leaves no half backup behind when it fails, and says so.

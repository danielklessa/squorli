LiveKit, the media server behind voice, camera and screen share, is raised from 1.13.7 to 1.13.9, and the client gets a fix for hearing someone who was already talking when you joined their channel. Desktop app 0.13.4 carries the same client.

## Before you update

- **Nothing to do for the database:** no migration, and no new variable. Installations with automatic updates take the server image by themselves once it is published.
- **The new LiveKit comes with the deploy files, not with `squorli update`:** `compose.yml` names the LiveKit version. To take it over, run the install script again and choose "Update": it fetches the new deploy files and replaces the LiveKit container; database, files and secrets stay. Until then your server keeps running LiveKit 1.13.7, which works with this version as before.
- **Installed by hand or as a Portainer stack:** download `compose.yml` or `portainer.yml` again (both name `livekit/livekit-server:v1.13.9`) and start the stack again.
- **Windows without Docker:** the package carries LiveKit 1.13.9; `squorli update` installs it with the rest.
- **Desktop app:** 0.13.4 carries the client's fix below. Older apps keep working with this server; the browser client that comes with the server has everything. No newer Squorli Directory is needed.

## Fixed

- **Joining a channel where someone is already speaking.** Their voice arrived while the client was still setting up your own microphone, and a moment later the client dropped the level meter it had just made for them. Their speaker highlight then came from the server with a delay, and if you had set their volume above 100 %, the boost that hangs on that meter was gone with it: you heard nothing from them until they left and came back or you moved their slider. The meter now survives joining, with the boost on it.

## Improved

- **LiveKit 1.13.9.** Two releases of the media server since 1.13.7, with fixes in the forwarding of audio and video: a VP8 quality layer is switched up only at a frame the decoder can start from, the layers a viewer asked for are sent again after every change of what is published, two viewers subscribing in the same moment no longer lose one of the subscriptions, and the connection quality shown is based on the usual recent packet rate, so a short pause no longer counts as a bad connection. The server also does less work per forwarded packet. Voice, camera and screen share were checked against 1.13.9 with the browser client before this release.

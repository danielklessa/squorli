Security fixes for rate limits, roles, reports, kicks and bans, stricter limits on passwords and a newer web server library. Update soon.

## Before you update

- **This release contains security fixes.** Take it soon; the points under "Fixed" say what they are about. Version 0.8.2 was never tagged or released, so this release holds its changes too.
- **Nothing to do by hand** for an installation made with the install script or the Windows package: no database migration, no new variable, no deploy file to fetch again. Installations with automatic updates take this version by themselves once it is published.
- **An installation set up by hand** (a copied `.env`, a Portainer stack): the server now refuses to start in production when `LIVEKIT_API_SECRET` is the placeholder of the template (`change-me-...`), because that value is public and lets anybody listen to the voice channels. The log says what to do: set a random value (`openssl rand -hex 32`) in the `.env` and in LiveKit's configuration. A secret under 32 characters, or the template's database password, only produces a warning.
- **Optional:** `compose.yml` and `portainer.yml` now drop all Linux capabilities for the server container and forbid new privileges. `squorli update` pulls the image only; to take this over, fetch the Compose file again (or add `security_opt: ["no-new-privileges:true"]` and `cap_drop: [ALL]` to the `server` service yourself).
- **Desktop app:** older apps keep working. Two actions the server now refuses (giving a member a role with more permissions than you hold, and deleting messages through a report without the permission) are still offered by them and answer with an error; desktop app 0.11.2 hides them.
- No newer Squorli Directory is needed.

## Improved

- **Wrong passwords of server accounts block longer each time:** ten wrong passwords within a minute block that account for 5 minutes, the next time for 15, then for an hour (a quiet day starts over). A new backup of a server account's key must use at least 600,000 rounds, which the app and the browser client always do.
- **The rules of use are linked** in the notice a member gets about a moderator's measure and under the form for a Squorli account inside the client. The browser client has it with this release.
- **The role menu and the reports list show only what you may do.** A role you cannot hand out because it holds permissions you do not have is no longer offered, and the buttons that delete messages in a report need the permission to manage messages.
- **Direct message text stays out of notifications** until a member switches it on (Settings > Sounds, "Show the text of direct messages in the notification"). Direct messages are end-to-end encrypted, but the system may keep a notification's text in plain text. Mentions in channels keep their own switch.
- **Web radio:** an address that is not a playlist is refused when its host is an internal address, so nobody can point the channel's listeners at a router or a machine in a home network. The blocked address ranges are longer.
- **The server tells you when nobody is the owner yet** and nothing names one (neither `OWNER_PUBLIC_KEY` nor `OWNER_SETUP_CODE`): it logs a warning at every start, so you sign in before anybody else does.
- **Browsers are told to use https for a year** when the server is reached over https (HSTS; not for `localhost`), and a server error no longer shows its internal message to the client.
- **The debug panel hides the session token** when you open it to share a screenshot.

## Fixed

- **Rate limits** were skipped by some requests; they now apply to every request they are meant for.
- **Roles:** a member who may assign roles could give themselves a role with permissions they did not hold themselves. Assigning a role now needs the same permissions as editing it.
- **Reports:** closing a report with "delete" now needs the permission to manage messages in that channel, and deleting a person's recent messages needs a higher rank than that person, as banning does.
- **Kick, ban and account deletion** now also remove the person from the voice channel they are in; before, a modified client could stay in the room and keep listening.
- **A ban stays** when the banned person deletes their account.
- **Oversized messages** on the real-time connection (larger than 64 KiB) are refused.
- **Known vulnerabilities in libraries** are fixed by updating the web server, its static-file module and the database library (12 reported by `pnpm audit` before, none after).

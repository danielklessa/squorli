Plugins can now come from a catalogue: plugins that Squorli signed, searched and installed with one click in the administration. A signed plugin may fetch from the internet, from the hosts it names and nowhere else; the first one is game news. One migration and two new variables with defaults. Desktop app 0.17.1 follows with the same client.

## Before you update

- **Nothing to do by hand.** Installations with automatic updates take this version by themselves once it is published. The update adds two columns to the plugins' table in the database (they cannot be taken back); `squorli update` backs up first, as always.
- **Your server contacts GitHub for the catalogue, and only when somebody opens it.** In Administration > Plugins, "Katalog öffnen" makes the server fetch the list of signed plugins from https://github.com/danielklessa/squorli-plugins, and an installation downloads the plugin's signed file from there. Nothing about your server or its members is sent. Set `PLUGIN_CATALOG=false` in `.env` to have no catalogue; the server then never asks.
- **A plugin with the network makes your server ask other hosts.** Only a plugin that carries Squorli's signature can get that right, only after an owner read the list of its hosts and switched it on, and only with plain requests to those hosts. Set `PLUGIN_NET=false` to allow no plugin the network; such plugins are then not installed.
- **New variables, each with a default:** `PLUGIN_NET` (`true`) and `PLUGIN_CATALOG` (`true`). A Portainer stack passes them on only with the new stack file from the repository; without it the defaults apply.
- **Desktop app:** 0.17.1 follows with the same client. Older apps keep working with this server: they have no catalogue, show a plugin's card as a line of text and a list in a plugin's settings as a notice that a newer app is needed. The browser client comes with the server.
- **New, and not yet proven in the field.** The catalogue, signed plugins and cards were tested in automatic tests, against the published catalogue and on test installations. They were not yet run on the package for Windows or on a server in daily use.

## New

- **The plugin catalogue.** Administration > Plugins > "Katalog öffnen" lists the plugins Squorli signed, with a search field, what each may do and which hosts it asks. An owner installs or updates one with a click; the server downloads the signed file itself and installs it only when its signature holds and it is the very file the list names. The same list is at https://squorli.com/en/plugins/.
- **Signed plugins.** A plugin file can carry Squorli's signature, which your server checks itself. The administration then shows "Von Squorli" for Squorli's own plugins and "Von Squorli geprüft" for a plugin by somebody else that Squorli read before signing it. A signature that Squorli takes back reaches your server with its next update; the plugin stops then.
- **The network for signed plugins.** A signed plugin may fetch data from the internet: from the hosts its file names, over https, with plain requests that carry nothing but the address. The confirmation before switching it on names every host. An unsigned plugin never gets this right.
- **Game news** is the first such plugin, in the catalogue. It posts into channels you pick: announcements or only patch notes of the games you follow on Steam (you list them in its settings, by name, Steam number or store link, and choose per game), games that are free to keep right now (Epic Games Store, and Steam, GOG and others via GamerPower) and new graphics drivers from NVIDIA and Intel. AMD's drivers are missing: there is no source for them a program may read.
- **Cards.** A plugin's message can be a card: a title that links somewhere, a formatted text, a small picture in the corner and a large one below. Your server fetches the pictures itself and serves its own copies, as it does for link previews, so no member's app asks a foreign host. Game news posts cards.
- **Lists in a plugin's settings.** A plugin can ask for a list of entries that an admin adds and removes, and it can check what was entered before the settings are saved and say what is wrong at the field.
- **For authors of plugins:** interface version 2 with `squorli.net.get`, the field type `list`, the event `settings.check` and cards; version 1 plugins run unchanged. Plugins are submitted for a signature by pull request at https://github.com/danielklessa/squorli-plugins, each with a test that runs it in the server's sandbox. The guide: https://squorli.com/en/docs/plugins/ (German: https://squorli.com/de/docs/plugins/).

Sessions bound to the device and an idle timeout (security audit, stage 3).

## Before you update

- **Nothing to do by hand.** The one database change (a flag per session) runs at the start. Installations with automatic updates take this version by themselves once it is published.
- **Desktop app:** older apps keep working, their sessions are simply not bound (see "New"). Desktop app 0.12.0 brings the binding; the browser client comes with the server. A session from before this version is not bound either; every sign-in from now on is.
- No newer Squorli Directory is needed.

## New

- **A session is bound to the device that signed in.** Until now a session token alone was the key to an account on this server for up to 30 days: copied out of a browser profile, a screenshot of the debug panel or a log, it worked from anywhere. Now a client that names its device at the sign-in (every browser and desktop app since the device keys of 0.7.0) gets a session that works only together with a fresh signature of that device's key: on every request and when the real-time connection opens. A copied token opens nothing without the device. Nothing changes for the user; a device whose clock is off is told the server's time and corrects itself.
- **Sessions end after 14 days without use.** A session that was not used for `SESSION_IDLE_DAYS` (default 14) ends before its 30 days (`SESSION_TTL_DAYS`, as before); an open connection counts as use. `SESSION_IDLE_DAYS=0` switches the idle timeout off. Both can be set in the `.env`; nothing needs to be set.

Less personal data in the logs, and the reverse proxy templates are now tested.

## Before you update

- **No database migration, no new desktop app, no newer Squorli Directory.** `squorli update` brings the new server.
- **Fetch the deploy files again for the log changes:** `squorli update` only pulls images. Run the installer again (it replaces the files under `deploy/`, keeps a `.bak` of files you changed and leaves `.env` alone), or copy the changes by hand: the `x-logging` block and the `logging:` lines of `compose.yml`, and `level: warn` in `livekit/livekit.yaml`. Portainer: take the new `deploy/portainer.yml`.
- **nginx in front of the server:** raise `client_max_body_size` to `30m` (see Fixed).
- **Portainer:** the stack now uses the public image `ghcr.io/danielklessa/squorli-server:latest` when `APP_IMAGE` is empty.

## Improved

- **No visitor addresses in the logs.** The server no longer writes a line per request, so its log holds no IP address per visit; requests that end in a server error are still logged, without the address. Three security events keep the address: a rate limit reached, a wrong password for a server account's key, a connection closed for flooding. `LOG_REQUESTS=true` brings the full request log back for troubleshooting, `LOG_LEVEL` sets the level.
- **LiveKit logs warnings only.** At its former level it wrote every participant's IP addresses on every join. Set `level: info` in `livekit/livekit.yaml` for a while when you debug a connection.
- **Logs are rotated.** Every container keeps at most 3 files of 10 MB; Docker kept them forever before. For a time limit (for example 14 days) switch to journald, as described in the logging notes of the repository.
- **Caddy as an existing proxy.** A template `deploy/proxies/Caddyfile.external` for a Caddy you already run for other sites.
- **Tested proxy templates.** nginx, Traefik and Caddy are now started in front of the server on every change and checked through: the WebSocket, `/rtc`, the member's address, a full-size upload and the setup check.

## Fixed

- **25 MB attachments behind nginx.** The nginx template allowed 25 MB per request, so an attachment of the full default size failed with "413 Request Entity Too Large". The template now allows 30 MB.
- **Traefik template.** The labels now name the Docker network Traefik reaches the server on (`traefik.docker.network`). Without it Traefik could pick the internal network and answer with 502/504 or hang; if you use the template, add the label with the name of your Traefik's network.
- **Query secrets in "not found" log lines.** With the request log switched on, a request to an unknown address could write the status API key into the log; it is hidden now like everywhere else.

A fix in the browser client: ending a screen share with audio no longer silences the presenter for listeners who had turned them up.

## Before you update

- **Nothing to do by hand.** No database change, nothing in the server itself changes; the image carries the fixed browser client. Installations with automatic updates take this version by themselves once it is published.
- **Desktop app:** the same fix is in desktop app 0.12.5. The fix sits in the listener's client, so the people who could not hear the presenter need the new version, not the presenter.
- No newer Squorli Directory is needed.

## Fixed

- **A screen share with audio ending silenced the presenter** for everyone who had set that person's volume above 100 %, until the presenter switched channels or reconnected. The listener's client dropped the presenter's level meter when the share's audio track ended, and the volume boost above 100 % hangs on that meter. Now only the microphone track's end drops it.

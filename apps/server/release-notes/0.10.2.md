The first signed release: the image carries a cosign signature, the Windows package's checksum file the release key's, and `squorli update` checks both from now on.

## Before you update

- **Nothing to do by hand.** No database change, nothing in the server or the browser client changes; no new desktop app. Installations with automatic updates take this version by themselves once it is published.
- **Linux, installed with the install script:** this version is signed, but your `squorli` command checks signatures only after the installer has run once more (`sudo bash install.sh`, "Update": it rewrites the command). From then on `squorli update` refuses an image that was not signed by the release workflow. `IMAGE_VERIFY=off` in `.env` switches the check off, for a host without a way to the Sigstore services.
- **Windows:** `squorli update` to this version installs the public key and the check; from the next update on, the package's checksum file must carry the release key's signature. A package you point at with `-Package` and that has no `.sha256.sig` next to it is still installed, with a warning.
- **`stable` is the default now.** The installer, `.env.example`, the Portainer stack and the guides name `ghcr.io/danielklessa/squorli-server:stable`, the newest published release, instead of `latest`, which follows the development and is not signed. An existing installation keeps the tag it has; `squorli autoupdate on` offers the change.

## Improved

- **Signed images.** Every release's image is signed with cosign after the operator approved the release. `squorli update` and the installer verify the signature before anything of the new image runs; to verify by hand see the README, "Signed releases". Development images (`latest`) are not signed and are started with a note instead of a check.
- **Signed Windows packages.** The release attaches `squorli-server-<version>-windows-x64.zip.sha256.sig`, the checksum file's signature by the release key (Ed25519). `squorli update` checks it with the key that ships in the package, then the SHA-256 as before.
- **Build provenance.** Every image the CI pushes carries GitHub's provenance attestation (which workflow built it from which commit): `gh attestation verify oci://ghcr.io/danielklessa/squorli-server:v0.10.2 --owner danielklessa`.

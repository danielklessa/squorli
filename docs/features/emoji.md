# Feature notes: Emoji (font, conversion, picker)

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked. Standing rules live in the `AGENTS.md` of the area. Whoever changes the feature adds or updates its entry here in the same step.

Code: `apps/web/src/emoji/`, `EmojiPicker.tsx`, `tools/emoji.mjs`.

**Emoji in the chat (17 September 2026, user's wish):** font, automatic conversion and a picker, for channels and direct messages alike.
- **Font: Noto Color Emoji** (SIL OFL 1.1, Google; free to redistribute, complete, kept current). **Self-hosted files in the repo:** `tools/emoji.mjs` downloads the `unicode-range` slices that Google Fonts serves to Chromium (COLRv1, v47: 11 files, 10 kB to 709 kB, about 2 MB in total) once into `apps/web/src/emoji/font/` together with `OFL.txt` and `font.json`, and writes `apps/web/src/emoji/font.css`; after that only our own server delivers them (no CDN, no font service at runtime), and a browser fetches only the slices whose emoji occur. The files are committed (about 2 MB of binaries) because the Docker build has neither `tools/` nor should it depend on Google. **Do not use `@fontsource/noto-color-emoji` (5.3.1):** its slices carry COLRv1 and SVG tables but render as blank boxes in Chromium; that was the first attempt and the user saw no emoji at all (found and fixed on 17 September 2026 with headless Chrome screenshots; the package's unsliced file renders but weighs 5.7 MB). **Safari has no COLRv1:** `styles.css` names the font only inside `@supports (font-tech(color-COLRv1))` (root stack and `.emoji`), so Safari keeps Apple Color Emoji instead of blank glyphs; Chromium 108+ and Firefox 107+ get Noto. Windows shows no flag emoji by itself, which the font also fixes. `main.tsx` imports `font.css`. The font is the **last** entry of the root `font-family` (it also covers digits, `#` and `*` for keycaps, which the text font must win); in messages every emoji is a `<span class="emoji">` with the font first, 1.3 em, and a message of nothing but up to 12 emoji is shown large (`.md-jumbo`). Verified with headless Chrome against the built CSS: emoji in text, large emoji, root stack, the message input, the picker grid, flags, skin tones, ZWJ families and keycaps render; digits stay in the text font. Not checked: Firefox, Safari.
- **Automatic conversion at display time** (`emoji/convert.ts`, called from `markdown.ts`; messages stay stored as typed, so nothing is lost and older messages convert too): shortcodes `:smile:` (the Markdown habit; union of the GitHub, iamcal = Slack/Discord style and emojibase sets, 3370 names, `emoji/shortcodes.ts` is part of the main bundle, lookup with `Object.hasOwn` so `:constructor:` finds nothing; not directly after a letter or digit, so `12:30:45` stays) and classic emoticons (`:)`, `;-)`, `:D`, `:P`, `<3`, `xD`, `^^` ... in `EMOTICONS`, deliberately few: only as a word of their own, so `http://`, `C:/` and `xDrive` stay; `8)`, `:3`, `D:` are left out on purpose). Real emoji are found by a Unicode-property regular expression (since 6 October 2026 the protocol's `EMOJI_SOURCE` in `primitives.ts`, which the server's reaction check and the direct messages' reaction instruction use too, `docs/features/reactions.md`; flags, keycaps, tag sequences, ZWJ sequences, skin tones; characters with text presentation such as ©, ™, ↔ only count with U+FE0F). Never inside code spans, code blocks or addresses; a backslash keeps a form literal (`\:)`). The `title` of a converted emoji shows what was typed. A test checks that every emoji of the picker is recognized as exactly one emoji.
- **Picker** (`EmojiPicker.tsx`: `EmojiButton` in the composer of `ChatView` and `DmView`, smiley icon next to "Senden", as high as that button and without a background, also on hover: user's wish): own component (no picker library), a body portal opening upwards from the button (`menuPosition`), search field with focus, nine categories plus "Zuletzt verwendet", skin tone choice, preview line with name and shortcode. Names and keywords come in the client's language (`emoji/data.de.ts`, `data.en.ts`, generated from `emojibase-data` 17.0.0, MIT, dev dependency; about 1900 emoji each, lazy chunks of 55-67 kB gzip fetched when the picker opens); search covers name, keywords and the English shortcodes (`:thu` finds 👍). Inserts at the caret of the input (replacing a selection) and returns the focus there; Shift+click or Shift+Enter keeps the picker open; arrow keys move through the grid (8 columns, `COLUMNS` = the CSS grid), ArrowDown from the search enters it, Enter in the search takes the first hit, Escape closes. Hover/focus preview uses event delegation and memoized grids so the 1900 buttons do not re-render. Pure logic in `emoji/picker.ts` (tested). **Recently used and the skin tone are stored per device** (`chat.emoji.recent.v1`, `chat.emoji.tone.v1`) and deliberately not in the directory account (usage history; would need a protocol and directory change) - Claude's decision, confirmed by the user on 25 September 2026. The edit field has no picker. `pnpm emoji` regenerates font CSS and data after updating one of the two packages; the output is committed and not part of `pnpm build`.

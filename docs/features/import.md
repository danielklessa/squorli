# Feature notes: Import of a server structure (Discord server templates)

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked. Standing rules live in the `AGENTS.md` of the area. Whoever changes the feature adds or updates its entry here in the same step.

Code: `packages/protocol/src/import.ts` (schemas, `discordTemplateCodeOf`), `apps/server/src/import/discord.ts` (template schema and the pure plan), `apps/server/src/import/fetch.ts` (fetching from Discord, cache), `apps/server/src/routes/import.ts` (preview and import), `apps/web/src/ImportTab.tsx` (Verwaltung > Import), `apps/server/scripts/smoke.mjs` (the import checks against a real template).

**Taking a Discord server's structure over (22 September 2026; user's question "Können wir die Möglichkeit einbauen die Struktur eines Discord Servers zu übernehmen?", decisions: the role "Gast" stays as it is, the import only adds and never replaces, Discord's bitrates are taken over):**

- **Source: a Discord server template, nothing else.** The Discord server's owner creates a template in Discord's server settings (needs "Server verwalten" there; by Discord's rules community servers cannot create templates) and pastes the link (`discord.new/<code>`, also `discord.com/template/<code>` or the bare code) into Verwaltung > Import. Discord's endpoint `GET https://discord.com/api/v10/guilds/templates/<code>` answers **without any authentication** (checked 22 September 2026: an unknown code gets `{"code": 10057, "message": "Unknown server template"}` while `/guilds/<id>/channels` gets 401), so no bot, no application and no token are needed, and no user token is ever involved (that would break Discord's terms). The chat server fetches the template itself (`import/fetch.ts`: 8 s timeout, 4 MB cap, one host, so no address rules needed; a template is cached for a minute per code and requests in flight share one fetch, so the preview and the import that follows read the same thing). A bot path for community servers was considered and not built until somebody needs it.
- **What a template holds:** categories, channels (type, name, position, topic, bitrate, permission overwrites) and roles (name, color, permissions as a decimal string of Discord's 64-bit set, ordered by array position, `@everyone` first), plus the AFK channel. Never members, messages, emojis, webhooks or bans.
- **Plan first, then the import (`planDiscordImport`, pure, tested):** `POST /api/import/discord/preview {code}` returns an `ImportPlan`; `POST /api/import/discord {code, categories, channels, roles, afkChannel}` builds the same plan again from the same (cached) template and creates the chosen entries in one transaction. Both routes need `MANAGE_CHANNELS` **and** `MANAGE_ROLES` (an import creates both), a member without them gets 403 `forbidden`. Errors: 400 `bad_code` (no template link), 404 `unknown_template`, 429 `discord_rate_limited`, 502 `discord_unavailable`, 403 `cannot_grant` (a chosen role has permissions the actor may not grant; the plan marks such roles `blocked` beforehand and the client does not offer them).
- **Mapping:** Discord types text/announcement/forum/media become text channels, voice/stage become voice channels, categories stay categories; directory channels and the like are `dropped` with `unsupported`. Order as Discord shows it: channels without a category first, then per category (categories by position), text before voice, each by position; here they get positions after the existing ones. Topic is kept (256 characters), Discord's bitrate in bit/s becomes the nearest of the client's steps in kbit/s (user's decision to take it over), stereo off. Roles: name (32 characters), color (`#rrggbb`, 0 = none), permissions translated where a counterpart exists (`mapDiscordPermissions`: Administrator, Manage Guild = Server verwalten, Manage Channels, Manage Roles, Kick, Ban, Create Invite, View Channel, Send Messages, Manage Messages, Attach Files, Connect = `CONNECT_VOICE` plus `VIEW_VIDEO` because on Discord connecting lets you watch streams, Stream = `STREAM_VIDEO`, Mute/Deafen/Move Members = `MODERATE_VOICE`); Add Reactions = `ADD_REACTIONS` since 6 October 2026 (`docs/features/reactions.md`); everything else (threads, emojis, nicknames, history, webhooks, events) falls away, nothing maps to `CONTROL_RADIO`. **Channel permission overwrites were dropped until 23 September 2026** (permissions applied server-wide); since then they are taken over, see the entry below. `@everyone` is dropped (`default_role`): the role "Gast" keeps its permissions (user's decision).
- **Only adding ("ergänzen", user's decision):** a category of the same name (case-insensitive) is reused (`existingId`), its channels go into it; a channel of the same name and kind in the same category is `exists` and not offered; a role of the same name is `exists`. Running the same import twice creates nothing. Nothing is renamed, moved or deleted. New roles are inserted **below** every existing role (positions 1..n in the template's order, the existing non-default roles move up by n so their order stays and nothing lands above anybody), and nobody gets them: members must be assigned by hand as before.
- **AFK channel:** offered only when the template has one, it is one of the imported voice channels, this server has none yet and the actor has `MANAGE_SERVER`; set inside the transaction only if `afk_channel_id` is still null (a fresh, empty channel needs no silencing and has no radio).
- **Feature flag:** `ServerState.importSources` (`["discord-template"]`) tells the client that the server offers the routes; older servers send nothing and the tab stays hidden (no `PROTOCOL_VERSION` bump).
- **Client (`ImportTab.tsx`):** intro with the three steps, link field, preview: one fieldset per category (a category that exists here is shown as "gibt es schon, Kanäle kommen hinein" without a checkbox), rows with icon, name and details (bitrate, topic, overwrites), roles with color dot and the translated permission labels, the AFK checkbox, the "Nicht übernommen" list, the note about permissions, a button "n Einträge übernehmen" (unticking a new category unticks its channels; greyed rows are `exists` or `blocked`). After the import the tab returns to the link field with the result line; the new structure arrives through the structure broadcast like any other change.

Checked (22 September 2026): protocol tests (`import.test.ts`: link spellings, schemas), server tests (`import/discord.test.ts`: permission bits, bitrate and color mapping, the order of a small template, duplicates, blocked roles, AFK offer), the smoke test against a built server on :3001 with the real public template `discord.new/JfppTU3CNvuD` (a FiveM template with 15 categories, 58 channels and 29 roles: preview, import of one category with 7 channels and two roles, role positions, second preview marks them as existing, second import creates nothing, cleanup, 403 for a guest; the checks are skipped with a notice when Discord answers 502/429), the real client in headless Chrome (the tab, the plan of that template, the phone width). Not checked: the bot path (not built), templates of community servers (Discord does not offer them), an import while members sit in a voice channel (nothing of theirs changes: no existing role or channel is touched).

**Overwrites are taken over (23 September 2026, with the channel permissions, `docs/features/channel-permissions.md`; user's wish: "Rechte sollen beim Discord import beachtet werden"):** the template's `permission_overwrites` of channels and categories are parsed for real (`{ id, type, allow, deny }`), each mask through `mapDiscordPermissions` and then masked to `CHANNEL_OVERRIDABLE` (`mapOverwrites`, tested); Discord's `@everyone` becomes an entry for the default role "Gast" (that is what keeps a private channel private; the decision "@everyone wird verworfen" was about the role's own permission mask, which still stays as it is), a role that already exists here by name resolves to that role, a role not taken over loses its entries, overwrites for single Discord accounts are counted (`memberOverwrites`) and dropped. Category overwrites go into `category_overwrites` and work through the live inheritance, which is Discord's sync. `D.MOVE_MEMBERS` maps to `MOVE_MEMBERS` now. The plan carries `overwrites` as a list and `private`; the tab shows "privat" with a lock and "n Kanalrechte werden übernommen" / "n Rechte einzelner Discord-Konten entfallen". Checked: `import/discord.test.ts` (a private category with an allow for one role, a read-only channel, the member overwrite counted), the protocol's `import.test.ts`; not checked against a real template with private channels.

# Feature notes: Notices (messages shown without their author)

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked. Standing rules live in the `AGENTS.md` of the area. Whoever changes the feature adds or updates its entry here in the same step.

Code: protocol `packages/protocol/src/permissions.ts` (`MANAGE_NOTICES`), `index.ts` (`Message.notice`, `SetNoticeRequest`); server `apps/server/src/routes/messages.ts` (`PUT /api/messages/:id/notice`), `db/schema.ts` (`messages.notice`), migrations 0043 (the column) and 0044 (the right, by hand); client `apps/web/src/ChatView.tsx` (the megaphone in the toolbar, the row without a head), `api.ts` (`setNotice`), `styles.css` (`.msg.notice`), the texts `chat.makeNotice`/`chat.unmakeNotice`/`chat.notice`, `perm.MANAGE_NOTICES`, `chanPerm.MANAGE_NOTICES`.

**Notices (6 October 2026, user's wish: "Man soll mit entsprechendem Recht eine Nachricht auch zu einer 'Kanalnachricht' (kann auch einen besseren Namen haben) machen können. Eine Kanalnachricht zeigt nicht mehr an wer sie geschrieben hat, nur noch die Uhrzeit und steht ganz links (also nutzt auch den Bereich in dem normalerweise der Avatar steht)."):**
- **The name:** "Hinweis" in German, "notice" in English (the user left the name open and accepted this one the same day; "Kanalnachricht" would read like a message *about* the channel). In the code everything is `notice`: `Message.notice`, `MANAGE_NOTICES`, `SetNoticeRequest`.
- **What a notice looks like:** the row has no avatar and no name. The time stands at the far left where the avatar normally is (`.msg.notice > .notice-time`, a fixed width so the texts of several notices line up), the text starts right next to it; the row otherwise behaves like a message (Markdown, attachments, link previews, reactions, the amber edge of a mention, edit box). The author is not shown anywhere on the row, not in a tooltip either (the user's wish is that it does not show who wrote it); the server still knows, so edit and delete rights, reports and the moderation log are unchanged. **A notice never groups** with its neighbours: it has no head to omit, and the message after it shows its head again even when the same person wrote it within the grouping time.
- **The right `MANAGE_NOTICES`** (bit 20, channel-overridable, label "Hinweise setzen"; Claude's decision inside the wish "mit entsprechendem Recht", accepted by the user the same day: a right of its own rather than `MANAGE_MESSAGES`, so a server can let people set notices who may not delete other people's messages). It sits in the text group between attaching files and `MANAGE_MESSAGES` (changing how a message shows is lighter than deleting it). **Migration 0044** gives it to every role that has `MANAGE_MESSAGES`; owners and administrators have it anyway; "Gast" and "Mitglied" do not get it. The Discord import maps nothing to it (Discord has no counterpart). Whoever has the right may turn **any** message of the channel into a notice and back, their own included; the author's rights do not matter.
- **The toolbar:** with the right, every message's hover toolbar carries a megaphone ("Als Hinweis anzeigen (ohne Absender)"), a notice a crossed one ("Wieder als normale Nachricht anzeigen"). `PUT /api/messages/:id/notice { notice }` answers the message and sends it to the channel as the existing `message.update`, so every client switches the row at once; the same value again answers the message without an event. 404 for a message one cannot see, 403 without the right, 400 for a body that is not `{ notice: boolean }`.
- **Protocol:** `Message.notice` has a default of `false` (a server from before sends none, a client from before ignores it); no `PROTOCOL_VERSION` bump. The permission is appended at the end (bit order is history).
- **Not done (Claude's decisions, accepted by the user on 6 October 2026):** no mod-log entry (setting a notice is not an action against a person), no notice in direct messages (they have no channel rights), no way to *write* a message as a notice right away (one sends it and marks it; a composer switch can follow if wanted), no distinct background or icon on the row beyond the missing head (the user asked for less, not more).
- **Checked:** typecheck of protocol, server and web; tests (protocol 151 with the overridable check, server 215, web 543; the message fixtures of two tests carry `notice: false`); `pnpm db:generate` produced migration 0043, 0044 was written by hand with its snapshot and journal entry; root build (the icons `megaphone` and `megaphone-off` in the subset). `pnpm smoke` 260 green against a scratch server on :3001 (`chat_smoke` recreated): the owner sets the notice and the channel gets the `message.update` with `notice: true`, "Mitglied" is refused with 403 and has no `MANAGE_NOTICES` after the migration, the history carries the flag, taking it back answers `notice: false`, a wrong body is a 400. A headless Chrome screenshot of the chat with the built CSS: a grouped pair, a notice with the time at the far left and its toolbar (crossed megaphone), the message after it with its head again, a notice with the amber mention edge, a normal message's toolbar with the megaphone. **Not checked:** the toggle in the running app against a real server, the role editor's and the channel dialog's new checkbox on screen (they list the permission groups generically), a notice with attachments or a link preview.

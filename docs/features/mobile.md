# Feature notes: Mobile app (iOS and Android)

Part of the project description (entry point: root `AGENTS.md`, section 0). Dated entries: what was built, the user's wishes and decisions, consequences, and what was and was not checked. Standing rules live in `apps/mobile/AGENTS.md`; the open work and the stages in `docs/PLAN-mobile.md`. Whoever changes the feature adds or updates its entry here in the same step.

Code: `apps/mobile/`, `apps/web/src/platform/mobileApp.ts`, `apps/web/src/backStack.ts`, `tools/mobile-icons.mjs`.

**Stage 1 begun: the shell for both systems (20 October 2026, user: "lass uns mit dem mobile plan beginnen"; `docs/PLAN-mobile.md` stage 1):**

- **The shell:** new workspace package `apps/mobile` (`@squorli/mobile` 0.1.0) with Capacitor 8.5.3 (`@capacitor/core`, `cli`, `android`, `ios`; plugins `@capacitor/app` 8.1.2, `@capacitor/keyboard` 8.0.6; all at least three days old, the rule of `../squorli-renovate`), the Android project (Gradle) and the iOS project (Xcode, Swift Package Manager, Capacitor 8's default) generated by `cap add` on Windows and committed. `scripts/sync.mjs` copies `apps/web/dist` into `www/` and runs `cap sync`. One build for every shell, as decided on 25 September 2026 (decision 1).
- **The page in the app:** `scripts/appIndex.mjs` gives the app's `index.html` the Content-Security-Policy of the desktop app as a meta tag (Capacitor sends no headers; `frame-ancestors` left out, a meta tag cannot carry it), `viewport-fit=cover` (only in the app: the browser keeps its page as it is, `docs/features/home-screen.md`) and no manifest link.
- **`Platform` for the app** (`platform/mobileApp.ts`, third implementation, `kind: "mobile"`): recognised by Capacitor's native bridge (`window.Capacitor.isNativePlatform()`, set by the shell before any script runs), no home server, the fixed directory `https://directory.squorli.com` (a page from the Vite dev server takes `VITE_DIRECTORY_URL` or the local one), `mobile: true`, notifications and deep links not yet, links through `window.open` (both shells hand a new window to the system's browser). `@capacitor/app` and `@capacitor/core` are dependencies of the web client but a lazy chunk of 8 KB that only the app loads (checked in the build: the main bundle has no Capacitor code).
- **Android's back button** (`platform.window.back`, `backStack.ts`): every dialog, menu and sheet registers while it is open (`useBackClose`, next to its Escape handling: the confirmations of `dialogs.tsx`, `ContextMenu` and so every menu built on it, settings, administration, channel dialog, "Server hinzufügen", reports, notices, camera picker, reaction roles, vote kick, the emoji picker, the rail's menu, the phone's voice sheet). Back closes the newest overlay, then the phone layout's slid-in member list, then goes from a chat or the stage back to the channel list; with nothing left the app goes to the background (`App.minimizeApp`). Without a listener Capacitor would end the app at the start page, and a voice connection with it.
- **Native parts:** permissions for microphone and camera (Android: RECORD_AUDIO, MODIFY_AUDIO_SETTINGS, CAMERA, neither feature required; iOS: `NSMicrophoneUsageDescription`, `NSCameraUsageDescription`, English for now), Capacitor 8's System Bars edge to edge with the client's existing `env(safe-area-inset-*)` padding, the Keyboard plugin (iOS resizes the web view), the dark ground `#0C1424` behind the page, the app's version from `apps/mobile/package.json` in both projects (Android's `build.gradle` reads it, `sync` writes it into the Xcode project; build number major * 1000000 + minor * 1000 + patch), `appendUserAgent` `Squorli-Mobile/<version>`.
- **Icons and start screens from the brand package** (`tools/mobile-icons.mjs`, after the user's correction the same day: "könntest du dich bitte für die splash und launcher screens an die brand halten"; my first version had the icon mark alone on the start screens): launcher icons with the icon mark on the dark ground (Android legacy, round, adaptive with a themed layer from the white mark, the iOS icon without alpha channel), the start screens with the default logo `squorli-logo.svg` (icon mark above the light wordmark) on Night: iOS's launch screen, Android 12's start window (`windowSplashScreenAnimatedIcon`, inside its 192 dp circle) and older Android (a layer list with the logo unscaled in the middle, instead of the template's stretched pictures, which would distort the logo on another screen shape). The tool measures the drawn geometry of each SVG (strokes included), centres it, keeps the clear space, falls back to the icon mark where the logo would stay below 160 px (Android's mdpi start window) and to the small mark below 32 px (none at the current sizes).
- **Third-party notices:** `tools/licenses.mjs` walks `MOBILE_ROOTS` (Capacitor's runtimes, the plugins), marked "mobile app only" (`docs/features/licenses.md`).

**Checked here and not in the plan before:** the directory's CORS accepts any origin (`origin: true` in `squorli-directory/apps/directory/src/index.ts`), as the chat server's does; neither the chat server's nor the directory's WebSocket checks the Origin header. So the app needs nothing on either side. Not changed yet: `signInOrigin` (protocol, `directory.ts`) keeps a site's host or the desktop app's origin for the device lists; the app's `https://localhost` would show as "über localhost", `capacitor://localhost` as nothing. A label of its own (and "Squorli App" in `labelFromUserAgent`, the user agent already carries `Squorli-Mobile/`) is a change of the directory contract in both repositories, left for a step of its own before a public version.

**Decisions of mine, confirmed by the user on 20 October 2026:** the app id `com.squorli.app` (final after the first upload); the origins as Capacitor's defaults; no backup and no device transfer of the app's data on Android (device keys belong to one installation); Android's back sends the app to the background instead of ending it; the version scheme and the build number; the permission texts; the CSP as the desktop app's; Capacitor packages pinned to exact versions.

**Checked (20 October 2026):** typecheck of all packages; all tests (mobile 12 new, web 582 with `backStack.test.ts` 3 and `mobileApp.test.ts` 2 new); root build; `sync` into both projects; the install step of the Docker build with the copied package files (`pnpm install --frozen-lockfile` passes with `apps/mobile/package.json`, fails without it, hence the new `COPY` line; the image itself was not built, Docker Desktop was not running); the built app page (`www/`) in headless Chrome as an Android phone with a stand-in for Capacitor's native bridge: the app's platform recognised (the login without a home server, `directory.squorli.com`), no CSP violation, one `backButton` listener after React's double mount, back with nothing open = `minimizeApp`, back with "Server hinzufügen" open closes the dialog and does not minimize, the second back minimizes. **Found and fixed by that run:** resolving a promise with the App plugin called `App.then()` ("not implemented"); the plugin is now used only inside the `then`. Pictures: every icon and start screen rendered as the systems show them (adaptive mask, circle, iOS rounding, the phone's launch screen with aspect fill).

**Not checked that morning:** anything on a device or in an emulator; see the next entry for the Android emulator. Still not checked: the Xcode build and anything on the iPhone (needs a Mac, `docs/PLAN-mobile.md` N1).

**First run on the Android emulator (20 October 2026, afternoon; user: "was müssen wir jetzt noch machen um Android zu emulieren?"):** Android Studio 2026.2 installed by the user with winget; its first-run wizard put the SDK under `%LOCALAPPDATA%\Android\Sdk` (platform-tools, build-tools 36.0.0, emulator 37.2.12, platform 37.0 with the Google Play x86_64 image, AVD "Medium Phone API 37.0": Android 17, WebView 145); `platforms;android-36` added by hand for the compileSdk, `ANDROID_HOME` and `local.properties` set (`apps/mobile/AGENTS.md`). The emulator runs on the Windows Hypervisor Platform next to Docker Desktop. `pnpm build`, `sync android`, the first Gradle build (43 s after the downloads), `cap run android --target emulator-5554` deploys in a few seconds. **Seen:** the app starts at `https://localhost`, Capacitor serves every asset locally, the sign-in page without a home server lies inside the safe areas on the dark ground with no strip on the right (the harness's narrow look was the harness), the `backButton` listener registers once (logcat), "Konto erstellen" opens the system's Chrome and back returns to the app. **Seen and left for the wording item of stage 1:** the client without a home server renders `DesktopLogin.tsx`, so the footer says "Squorli Desktop" (`desktopLogin.app`) and the hint under "Konto erstellen" speaks of a new tab (the web texts; the desktop app's `app.*.ts` are not loaded in the app). **Later that afternoon (the user on the emulator):** sign-in with the directory account and a voice join on the dev stack (`community-test.datlicht.eu`, LiveKit 1.13.9 in Docker on the same machine). The join first failed for 15 s and timed out: the signal WebSocket connected, but the dev LiveKit offered only the stale `LIVEKIT_DEV_NODE_IP` of `apps/server/.env` as ICE candidate while the emulator's STUN answer showed the machine's current public address (a DSL address that changes; `docs/DEVELOPMENT.md`). With the current address the room reports `participant active` over UDP; the router hairpins to its own public address (checked from the PC and from the emulator guest). **Not checked yet:** audio in both directions (the emulator's host microphone has to be switched on in its extended controls), the keyboard over the input, the permission questions, the start screen (too quick for a screenshot).

**The device lists (same afternoon; user: "der Useragent ist aber noch chrome im test"):** the emulator's sign-in stood as "Chrome auf Android über localhost". Built in both repositories (`docs/features/devices.md`, section of 20 October 2026): the app's user agent token makes the label "Squorli App auf Android" (iOS: "auf iOS"), its page origins become `MOBILE_APP_ORIGIN`, shown as "über die mobile App". The directory has to be deployed before its lists say so; the entries enrolled before change at the next sign-in.

**Safe areas (same evening; user: "In der Android App werden die safe areas nicht eingehalten"):** the server head of the channel list stood under the status bar and its icons under the clock: in the phone layout only the rail, the back header of the slid-in content, the member list's head, the composer, the stage's bar and the categorized modals took `env(safe-area-inset-*)`; the navigation column (`.left`, with the server head and the home side) and the status view (`.main.mobile-status`) did not, and the layouts above 700 px (a landscape phone) took nothing. Now `.app` carries every inset as padding outside the phone layout and left/right inside it, `.left` and `.main.mobile-status` take top and bottom, the rail also the bottom, `.modal-backdrop` keeps max(1rem, inset) on every side (styles.css, the comment at `.app`; the rule in `apps/web/AGENTS.md`, "Safe areas"). A browser reports zeros, so nothing changes there or in the desktop app. **Checked** on the emulator by screenshot: the channel list (server head below the status bar, the profile card above the gesture bar, the column's ground running under the bar), the chat view (back header and composer), the member list, the settings; web tests 583. **Not checked:** a landscape phone (the column layouts with the root's padding), the status view without a channel, iOS.
